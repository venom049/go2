# Go2 HIMLoco 1100 机载启动入口

安装位置：`/home/unitree/go2_himloco_stairs_1100`。

本入口参考机载旧工程 `GO2_STAIRS_TOMORROW_HANDOFF_20260824.md`、
`GO2_STAIRS_HANDOFF_20260824.md` 和 `deploy/robots/go2/STAIRS_KEYBOARD.md`
中的启动命令。所查旧工程没有独立的爬楼梯 `.sh` 启动文件，因此把它的
“进入控制器目录、eth0、显式模型、前台键盘操作、CSV 日志”整理成可执行脚本。

使用本次已部署的累计 1100 模型和独立保护控制器，不修改原工程、SDK、
系统服务或开机启动项。模型、配置和控制器 SHA-256 必须匹配才允许执行。
模型文件继续保存在原先新增的部署目录，不重复复制。

## 先检查

在机载终端中执行：

```bash
cd /home/unitree/go2_himloco_stairs_1100
./start_stairs.sh --dry-run
./start_stairs.sh --check
```

`--dry-run` 只校验文件和显示命令，不连接 DDS。
`--check` 只订阅状态并检查控制占用；退出码 3 表示控制仍被占用或姿态检查未通过，
不是安装失败。`--infer` 可进行 100 步实机数据只读推理，但不能证明闭环或爬梯效果。

## 启动入口及当前限制

```bash
cd /home/unitree/go2_himloco_stairs_1100
./start_stairs.sh
```

通过 SSH 操作必须使用交互终端 `ssh -tt unitree@192.168.123.18`。
上述无模式参数的入口会尝试启动电机控制程序，不能作为只读检查使用。

目前控制器仍有已知的站立保持/控制权交接问题。2026-11-03 首次接管时，
原厂控制释放后站姿未保持，保护检查在创建电机发布器之前拒绝启动。
**安装启动脚本没有修复这个问题，也不代表实机爬梯验证完成。**
脚本不自动释放原厂控制或切换服务；不要通过反复释放模式、关闭保护来绕过拒绝。
下一次实际运动前应先解决并验证受保护的站姿交接。

本副本的按键与旧策略不同：F 进入 FixStand；等待稳定后，1 选择唯一的
0.6 m/s 命令，G 才进入 Stairs。速度为命令值，不是实测速度。
X、空格、0 均锁存固定阻尼，不再执行旧策略的两次 X 趴下流程。
进入 Stairs 后软件限时 2 秒并锁存阻尼，不自动重新运行或恢复原厂控制。
初始 Passive 和结束阻尼不提供站立保持；原生线程卡死或网络中断时，
软件不能保证限时退出或阻尼送达。

每次运行的元数据和策略 CSV 在本目录 `logs/` 的独立子目录。
实际启动保持控制台直连 TTY，控制台输出不经过后台 tee；只读检查另存完整日志。

## 与旧启动命令的差异

- 改用累计 1100 模型、固定 0.6 m/s，以及本次独立保护二进制。
- 保留关节/数值保护和软件限时，不传入旧版的自动趴下、自动清零或关闭保护参数。
- 使用此二进制已经验证的 RPATH（系统 `/usr/local/lib` 和 ARM64 ONNX Runtime）。
  旧文档的 `/tmp/sdk2new_lib` 指向另一套 DDS 文件，哈希不同，不能直接照搬。
- 不会读取或保存 SSH 密码；不调用 sudo，不注册自启动，不执行 ReleaseMode。
