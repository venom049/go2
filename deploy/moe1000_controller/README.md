## 接口和保护

`MoePolicy.h` 直接从 SDK 顺序的单次加锁状态快照构造 225 维观测，按观测项拼接各自旧到新的 5 帧历史。
策略顺序为 FL、FR、RL、RR，每腿 hip/thigh/calf；12 维动作经 0.25 缩放和模型默认关节角偏移后映射回 SDK。
模型从具名 `actions` 输出读取；固定策略增益为 Kp=20、Kd=0.5，零目标速度、零前馈力矩，周期 20 ms。
已提交目标逆编码为上一动作，仅表示交给 SDK 的目标，不表示电机执行确认。

站立交接与策略控制分开：站立阶段沿用原交接流程 Kp=40、Kd=1；一次原厂模式释放前读取原厂指令，匹配瞬时 PD+前馈估算后，2 秒插值到映射后的默认站姿。
按用户本次明确授权，接管后站稳目标误差门槛改为≤0.30 rad；速度≤0.8 rad/s、倾角≤0.25 rad、陀螺仪各轴≤0.35 rad/s，连续 0.75 秒；15 秒不能满足则锁存停止。原厂指令转换的独立交接误差检查仍为≤0.18 rad；0.30 不改变目标角度范围或运行时 0.9 rad 跟踪保护。
站稳后由单独的速度选择和策略启动键门控，绝不自动进入策略。

最终发布边界统一检查实际和目标关节位置、逐轴速度、0.9 rad 跟踪误差、45°姿态、估算请求力矩、有限性、递增 tick 和 100 ms 停滞。
小腿应用阈值使用当前已安装 profile 的 **30 rad/s**；髋/大腿 30.1 rad/s。原 URDF 小腿值仍是 15.7 rad/s，30 是应用覆盖值，不是固件读回或厂家限值变更。
任一违规替换为锁存的固定阻尼（kp=0、kd=3、q/dq/tau=0），本进程无重新解锁；不裁剪违规关节目标继续行走。
策略最多运行 2 秒。两秒足够完成整段楼梯的假设未经验证；本控制器没有自主识墙停车。

文件身份同时固定 ONNX、部署参数、应用 profile 与控制器配置。源码仍保留原文件版权头。
默认启动只打印 dry-run；只读模式没有 LowCmd 发布者；实际接管仅经显式 protected handoff 和交互键请求。
普通 `--first-test-actuate` 直接接管路径已拒绝。

## 实际限制

只读推理、编译和数值校验均不等于闭环稳定或爬梯通过。原仿真还有位置/跟踪超限。
控制仍依赖用户确认的承重支撑和现场硬件急停。推理超时、100 ms 通信检查及两秒上限是软件保护，没有独立硬实时看门狗；线程/原生推理阻塞、SIGKILL、断电和网络故障可能使软件停止失效。
LowCmd 空闲检查不是控制权租约。发布和退出日志仅证明发布请求，不证明 DDS 送达或电机实际响应。
