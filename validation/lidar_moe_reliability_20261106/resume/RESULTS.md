## 当前链路

`L1 原始点云 /utlidar/cloud + /lowstate 机身 IMU → 保留逐点时间的去畸变 → 机身姿态约束的点到面平移配准 → 独立点云和基座位姿 → 两级楼梯、踏面、上平台及后墙 → 对齐、调速、腿部撞阶风险停车 → 原始 MoE + 目标硬限幅`。

默认算法不订阅原厂 `SportModeState`、`cloud_deskewed` 或 `robot_odom`。原始驱动与 LowState 仍来自原厂硬件服务，不能称为完全不依赖原厂。此前观测到释放 mcf 后原始点云和 LowState 继续，而派生数据停止；新版完整链路尚未在实际接管和运动中验收。

## 当前不能开始爬阶的两个实测原因

1. **脚底和雷达地面存在未解释的位置差。** 用户确认四脚着地后重新采集六秒，六个三扫描窗口推算出的四脚球面与点云地面的中位残差约 35.6 / 26.7 / 48.2 / 36.7 mm。关节速度最高约 0.143 rad/s。采集记录了脚力读数，但未做脚力标定；LowState 配对采用接收时刻减去先前观测的约 50 ms 源延迟，仅用于静止核查。当前不能确定误差来自物理外参、点云地面拟合/近场测距还是模型对应关系；没有用经验偏移消除。原厂 raw→base 点对应在亚微米数值量级复现，只证明复现原厂转换，不能证明转换后的 base 就与 URDF 物理基座一致。证据：`feet_grounded_alignment_result.json`、配套原始 JSON/NPZ。
2. **楼梯几何确认间歇失效。** 门控前只读中，52 次缺后墙、19 次中间踏面不满足平面条件、15 次缺上平台，另有高度一致性失败。重复提取同一立面是原因之一；扩大平面抑制或增加候选平面的离线试验未稳定改善，且出现额外可疑立面和更高时延，因此未部署候选，也没有降低三帧确认或填补未知区域。

下一步需要解决物理坐标与地面观测一致性，再改善原装 L1 对上平台/后墙的有效覆盖，之后才能分阶段验证接管后静止、平地运动和接近台阶。若保持原始盲策略，雷达风险保护可能选择提前停车；要持续保证抬脚与台阶几何匹配，还需要能使用地形信息的步态或落脚规划，以及相应训练与验收。
